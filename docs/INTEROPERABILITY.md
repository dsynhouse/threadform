# Wilcom interoperability and release 0.12

Reviewed 8 September 2026. Repository: https://github.com/dsynhouse/threadform

## What can cross the boundary today

| Data                                         | Transfer                                         | Fidelity and verification                                                                                                                                                  |
| -------------------------------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Actual needle movements                      | Native DST, PES v1, JEF, EXP                     | Independent pyembroidery decoding checks coordinates, colour changes and controls. Target controllers and Wilcom still need qualification.                                 |
| Artwork outlines                             | SVG                                              | Shape/colour artwork; importing SVG does not create a native Satin or Tatami object.                                                                                       |
| Complete editable Threadform object settings | `.threadform.json` and `object-map.json`         | Original curves, input methods, underlay layers, thread metadata, compensation and effects retained. These JSON files are consumed by Threadform, not Wilcom.              |
| Reconstructed embroidery objects             | Wilcom machine-file recognition                  | Inference from needle patterns. Satin, Tatami and Program Split can be recognized; this cannot guarantee original outlines, methods or grouping.                           |
| Exact editable EMB                           | Licensed object-level conversion, not configured | Requires the appropriate Wilcom entitlement, documented interface, native object construction and round-trip verification. No EMB writer or renamed substitute is shipped. |

Wilcom itself distinguishes native design objects from reconstructed stitch data. Its [object-recognition guide](https://docs.wilcom.com/embroiderystudio/e4/en/MainHelp/Production/convert/Object_recognition.htm) describes the loss of source-object fidelity and unsupported patterns. The [API portal](https://developer.wilcom.com/) describes licensed services; detailed integration documentation is account-controlled at [the API guide](https://apiguide.wilcom.com/). Public examples do not establish an arbitrary-outline-to-EMB contract. Do not implement a guessed endpoint or claim a successful EMB conversion from a file extension.

## Executed improvements

Release 0.11 adds a persistent, dimmable original-artwork layer, Convert scroll ownership for short windows, live column footprints, stage-aware Backspace and refined freehand input. See [release verification](qualification/release-0.11.md). Artwork display transforms do not alter stitches, thread assignments or qualification fingerprints.

- Canvas uses native non-passive wheel/gesture listeners. Pinch changes canvas zoom at the pointer; two-finger movement pans. Listeners clean up when the canvas unmounts. The playback needle uses a plus crosshair.
- Five underlay methods: Center Run, Edge Run, Zigzag, Double Zigzag and Tatami. Ordered enabled layers each retain spacing, maximum length, uniform inset and relative angle. They generate actual needle paths before the cover. Non-fitting layers report a warning. Legacy presets remain readable.
- Maximum satin stitch is an explicit saved parameter from 1 to 12.1 mm, default 7 mm. Long paths split at the selected threshold. It affects parallel Satin, Raised Satin and Columns A/B/C. Format/controller move limits remain separate.
- Auto-digitizing proposes Center Run plus Zigzag for sufficiently wide inferred columns, and Edge Run plus Tatami for area fills. User-customized layers are retained. These are inspectable heuristics, not Wilcom's proprietary algorithms or learned fabric physics.
- Imported chart matching uses CIEDE2000 on display RGB values. Users review alternatives, retain artwork hex colours and protect existing assignments. Different physical shade codes sharing one RGB value now cause a thread change; changing a chart label alone does not regenerate geometry. PES/JEF approximate palette entries distinguish consecutive physical changes.
- Handoff ZIP includes the editable project, SVG, a versioned object map, optional generated commands and checksums. Machine packages also include the object map. Source bitmap bytes are not embedded; the project retains its local/cloud asset reference and trace settings.

## Column behavior and reshape

| Input | Implemented behavior                                                                                                | Still distinct from full Wilcom parity                                                                  |
| ----- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| A     | Alternating points on opposite edges; independent corner/curve flags; paired rails; Enter/Space final-side handling | Full corner/smart-angle automation and vendor-specific smoothing are not replicated.                    |
| B     | First edge, Enter, second independent edge; unequal point counts; source nodes retained during resampling           | Correspondence uses our geometric parameterization and requires inspection on extreme turns.            |
| C     | Corner/curve baseline, Enter, default width or two width references; signed offset; mirroring reflects the offset   | Separate relative stitch-angle controls and all closed-loop joining variants remain qualification work. |

Reshape retains editable source points and Bézier handles, entry/exit controls and stitch angle. Generated penetrations are a separate inspectable view. Keeping these data separate prevents converting every tatami row into a source drawing object.

References: [Column A](https://docs.wilcom.com/embroiderystudio/28/en/OnlineHelp/Digitizing/input/input-20.htm), [Column B](https://docs.wilcom.com/embroiderystudio/28/en/OnlineHelp/Digitizing/input/input-22.htm), [Column C](https://docs.wilcom.com/embroiderystudio/28/en/OnlineHelp/Digitizing/input/input-15.htm), [underlay methods](https://docs.wilcom.com/embroiderystudio/28/en/OnlineHelp/Quality/stabilizing/stabilizing-7.htm), [underlay margins](https://docs.wilcom.com/embroiderystudio/28/en/OnlineHelp/Quality/stabilizing/stabilizing-9.htm), [underlay length](https://docs.wilcom.com/embroiderystudio/28/en/OnlineHelp/Quality/stabilizing/stabilizing-10.htm).

The current inset is uniform. Wilcom's independent side/start/end margins, negative joining margins and chord-gap adaptive running lengths remain planned. A screen hex value is not a physically calibrated thread colour. Use licensed chart data and measurements; official sources include [Madeira shade cards](https://www.madeira.com/embroidery-solutions/service/support/shade-cards) and [AMANN downloads](https://www.amann.com/company/download-center/).

Release 0.12 merges the reliability review and addresses concurrent saves, invalid payloads, account-outage handling, recovery retries, pagination and incomplete large fills. See [the complete audit](qualification/release-0.12.md). These fixes do not add a native EMB writer or establish physical machine qualification.

## Object-map schema version 1

Coordinates use millimetres, x right and y down. `objects` retains source order and includes disabled/reference objects with explicit `sewEnabled`. `inputMethod` records A/B/C or outline; `coverMethod` maps rail columns to Satin while `parameters` retains every source property. `underlays` is the ordered explicit/effective legacy configuration. `commandRanges` uses zero-based inclusive `start`, exclusive `end` indexes into the optional plan commands. Ranges describe underlay layers or cover/connectors, not Wilcom native object IDs. `conversion.nativeEMB` is always false for this export.

Any future licensed adapter must declare supported object/effect mappings, fail visibly for unsupported semantics, retain credentials server-side and store the returned file with its input project hash. Acceptance requires reopening the actual EMB in the specified EmbroideryStudio version and verifying object types, coordinates, holes, rails, underlays, ties, compensation, thread codes and sequence. Comparing two machine decoders alone is insufficient.

There is no physical artboard maximum. Finite-number validation, computation/memory budgets, upload sizes and controller binary constraints are real engineering limits. Removing the 350,000-command interactive guard without replacing its memory model would make large designs fail through memory exhaustion. Large-design streaming is therefore a separate infrastructure task, not a hidden promise of infinite browser capacity.
